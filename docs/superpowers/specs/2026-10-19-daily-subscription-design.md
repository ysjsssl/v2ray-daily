# 每日订阅筛选服务

用户目标：每天获取 `https://clashgithub.com/wp-content/uploads/rss/YYYYMMDD.txt`，真实测试各节点，仅发布可用节点，并保持客户端订阅地址不变。用户选择 GitHub Actions 运行。

## 运行与发布

- 日期使用 `Asia/Shanghai`，默认北京时间每天 09:20 运行，另提供手动触发和代码更新后触发。
- GitHub 仓库默认分支保存源代码与 `subscribe/` 输出；固定链接使用公开仓库 raw 文件地址。
- 当前连接没有可访问仓库，不编造仓库或在线订阅地址。先交付可部署工程，再接入用户提供的仓库。
- 不创建功能不等价的聊天提醒。GitHub Actions 工作流本身负责持续更新。

## 数据与检测

- 下载支持 Base64 与明文 URI 列表；支持 VLESS、VMess、Shadowsocks、Trojan，不能解析的条目在报告中注明。
- 相同连接配置但名称不同的节点只测试一次；不同凭据或传输参数必须分别测试。
- 原始 URI 保存在成功输出中，不向第三方订阅转换服务发送节点凭据。
- 每个节点启动独立 Xray 出站和本地 SOCKS 入站，出站无 DIRECT 回退。
- curl 强制使用 SOCKS5 代理及远端 DNS，验证 HTTPS 证书，两个 HTTPS 204 地址均通过才算可用。
- 超时默认 10 秒、并发 8、最多接收 2000 行与 5 MiB 源文件；禁止私网、保留地址和解析到非公网地址的节点。
- 不测试 UDP、带宽和流媒体解锁；云端检测结果不保证用户本地可达。

## 输出与故障

- `subscribe/v2ray.txt`：通过检测的原始 URI 组成的 Base64 订阅。
- `subscribe/clash.yaml`：Mihomo 兼容配置，保留 TLS、REALITY、WS、gRPC 与基础 XHTTP 参数。不能无损转换的条目仅保留在 V2Ray 输出并在报告中注明。
- `subscribe/status.json`：最近一次成功发布信息和不含凭据的逐节点报告。
- `.run/report.json`：本轮报告，失败时作为 Actions artifact 保留。
- 下载失败、所有节点失败、核心运行异常均不覆盖既有订阅；没有可转换的 Clash 节点时保留旧 Clash 文件并在报告中明确说明。
- 使用同一 git 提交发布订阅及状态文件；失败任务不会发布半份更新。
- Xray 固定官方版本与 SHA256。所有临时核心配置与日志留在临时目录，工作流不上传含凭据的配置。

## 验证

单元测试覆盖 URI 解析、日期时区、去重、传输映射、失败保留与 curl 强制代理。集成测试用本地 VLESS 服务和 HTTPS 204 服务验证真实代理链路，并验证错误凭据被剔除。真实源的检测结果单独记录，环境限制不能当作节点永久失效。
